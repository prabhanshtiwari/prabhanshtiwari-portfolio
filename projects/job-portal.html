Job Portal.

A MERN-based job platform where students discover opportunities and recruiters publish jobs and manage applications.

01 / THE BRIEF

One platform, two user journeys.

Job seekers need a clear way to find openings, apply and follow application progress. Recruiters need a separate workspace to publish roles and review applicants. The project brings both workflows into one application with role-based access.

02 / THE APPROACH

Separate experiences, shared platform.

The application is organised into a React client and a Node.js/Express server. Students and recruiters use role-specific functionality, while JWT-based authentication and authorization protect access to the relevant parts of the application.

01 / STUDENT

Find and follow opportunities

  • Browse and search available jobs.
  • Apply to a job through the application workflow.
  • Track application status from the student dashboard.
02 / RECRUITER

Publish and manage openings

  • Create and manage job postings.
  • View applicants for posted jobs.
  • Update or remove listings from the recruiter dashboard.

03 / IMPLEMENTATION

What I built

  • Implemented registration and login using email/password authentication with JWT-based authentication and authorization.
  • Separated student and recruiter capabilities through role-based access.
  • Added job browsing and search, job applications, and application-status tracking for students.
  • Added job creation, listing management and applicant review workflows for recruiters.
  • Built the client with React, React Router, Axios, Tailwind CSS and shadcn/ui components.
  • Built the server with Node.js, Express.js, MongoDB and Mongoose.

04 / APPLICATION ARCHITECTURE

How the parts connect

The following is a high-level view based on the repository’s documented client/server structure and technology stack.

01 / CLIENT React application React Router · Tailwind CSS · shadcn/ui · Axios
↓ HTTPS / API requests
02 / SERVER Node.js + Express.js Application logic · JWT authentication · Role-based authorization
↓ Data access
03 / DATABASE MongoDB + Mongoose Persistent application data

Client and server separation

The repository keeps the frontend and backend in separate Client and Server directories.

Role-aware access

Student and recruiter actions are separated so each role is presented with the workflows relevant to it.

Reusable UI system

Tailwind CSS and shadcn/ui provide the interface foundation, while Framer Motion is used for interface animation.
